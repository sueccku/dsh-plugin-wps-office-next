# 共享执行契约（细则）

本文件是 `wps-office-next` SKILL.md §3/§5/§6 的展开。只在需要判断"这一步该不该保存 / 这个错误该不该重试"时读。

## 1. 目标：当前能做到什么，做不到什么

**没有 documentId。** 工具层和桥都没有"文档句柄"这个东西。目标解析的实际规则：

| 应用 | 目标怎么定 | 可传的作用域参数 |
|---|---|---|
| 文字 | **活动文档**（跟窗口焦点走） | 少数工具支持 `name`（如 `close_document`、`switch_document`），读/写正文的动作没有 |
| 表格 | **活动工作簿**里的某张工作表 | `sheet`（名字或序号）；跨工作簿要先 `switch_workbook` |
| 演示 | **活动演示文稿** | `presentationName`；`set_active_target`（`wps_call`）可改全局焦点 |

**可用的身份读回**（写前写后各读一次，用于核对是否落到同一目标）：

| 应用 | 读身份的工具 | 返回 |
|---|---|---|
| 文字 | `wps_word_get_active_document` | `name`、`path` |
| 表格 | `wps_excel_get_sheet_info` | `workbookName`、`workbookPath`、`currentSheet` |
| 演示 | `wps_ppt_get_slide_info` | `presentationName`、`presentationPath`、`slideIndex` |

协议：**动手前读一次身份 → 操作 → 再读一次身份与内容 → 两者一致才算落到目标上。**
不一致（名称/路径变了）说明焦点在调用之间被切走：停止对旧目标的后续写入，重新解析目标。

这条**只能缓解**风险，不能消除：两次调用之间的窗口切换仍然存在竞争窗口。多文档场景宁可先 `close_document` 收掉不相关文档，或在任务开始就串行处理。

## 2. 结果字段怎么读

| 字段 | 含义 | 该怎么用 |
|---|---|---|
| `success` | 不变量：**`true` ⟺ 你要求的事全部生效** | 只看这一个也不会被误导 |
| `error` | 失败原因（含动作名与"下一步"） | 原样转述，不要改写成"部分成功" |
| `partial` | `true` = 部分生效 | 先读已生效范围，只补做缺失部分 |
| `shortfalls` | 你要求但**没做到**的条目清单 | 逐条处理；这是 `success:false` 的原因 |
| `warnings` | 你没要求的坏消息（探测/清理失败），主操作已完成 | 涉及用户关心的结果时如实转述 |
| `data` | 动作的结构化返回 | 用它做核对，不要从正文散文里猜 |

`wps_call` / `wps_execute_method` / `wps_batch` 的正文是**桥的原始 JSON**，原样透传。要拿结构化字段就自己解析它。

## 3. 保存、副本与备份

| 用户意图 | 做法 | 注意 |
|---|---|---|
| 改现有文件 | 改完 `wps_common_save` | **覆盖磁盘原件**，不产生回退点 |
| 保留原件 | 先 `wps_common_save_as {outputPath}` 建工作副本，确认后续改动落在副本上 | 另存后**活动目标会变**（变成副本），要用身份读回确认 |
| 新建并落盘 | 定输出路径 → 写完 → `save_as` → 核对文件存在 | 未落盘的新文档没有路径 |
| 未落盘 + 要求"保存并关闭" | 先 `save_as` 到明确路径，成功了再关 | 没有路径时工具会**明确报错并保留文档打开**，不会丢弃内容 |
| 用户没提关闭 | **不关** | 不要顺手清掉用户的窗口 |

`wps_common_save_as` 的路径键是 `outputPath`（不是 `path`）。

**不要无条件创建备份。** 副本策略与任务影响范围、用户意图绑定：用户明确要保原件时才建副本。

## 4. 失败分流

| 情况 | 判据（错误长什么样） | 动作 |
|---|---|---|
| 调用参数错误 | `Missing required parameter: X` / `未知参数: X（动作：…）可选参数: …` / `参数 X 的形状不对` | 按错误里给的名字**改一次**；不要猜别名反复试 |
| 插件内部映射错误 | `unknown parameter(s) for 'xxxAction': key \| accepted: …` —— 这里的 `accepted` 是**桥**接受的键，不是你的参数名 | 改自己的参数修不了它：记下 action 名与原始错误，换等价工具或如实上报 |
| 能力不存在 | `unknown tool` / 明确说"没有对应工具" | 说明限制，用当前可验证的替代做法；不要拼造工具名 |
| 越界 / 前置条件 | `no presentation is open` / `No active document` / 页码越界 | 先满足前置条件（打开/新建、换页码） |
| 部分生效 | `partial: true` + `shortfalls` | 读已生效范围，只补缺失部分 |
| 超时 | `操作超时：… 状态未知` | 重新连接 → 核对后置条件 → 再决定是否重试 |
| warning | 正文里的「注意（N 条…）」 | 转述影响；不要因为 `success:true` 就说完全成功 |
| success=false | `success:false` | 不要当成功；原始错误如实报 |

**超时后禁止盲目重放非幂等操作**（`insert_text`、`add_slide`、`add_list_row`、插入图片、追加行…）。先读回确认上一次有没有落地。

## 5. 验证清单

写数据 / 写公式 / 改格式 / 排版 / 保存 / 页序 / 跨应用各自最少要核对什么，见 SKILL.md §5.2。
补充两条：

- **非目标部分也要检查**：多文档场景核对"另一份文件没有被改"（用身份读回 + 关键内容抽查）。
- **文件存在 ≠ 内容正确**：保存类操作的验收是"独立读一次内容/结构"，不是"输出文件在磁盘上"。
