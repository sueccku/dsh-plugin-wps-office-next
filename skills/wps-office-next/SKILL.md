# WPS Office（Windows / COM）

本技能覆盖 WPS 表格、文字、演示三个应用，工具名形如 `mcp__wps-office-next__<工具名>`。
三个应用各自的流程见 `wps-excel` / `wps-word` / `wps-ppt` 技能；本文件是共享执行协议。

## 1. 适用范围与路由

- 读、写、排版、计算、导出、转换本机 WPS 里的文档 → 本技能。
- 目标是一个**文件路径**（不管它现在有没有打开）→ 先打开它，不要让用户自己去点。
- 只要求"产出一份 Office 文件"、不依赖 WPS 的运行状态 → 也可以用宿主的其它能力生成；两条路都行时按用户要求选。
- 只要答案不依赖真实文档（纯文本推理）→ 不必调用本技能。
- **范围边界**：PDF 输入/合并/拆分、打印/打印预览、云文档协作、手机端、WPS AI、OLE/活链接、水印、文档属性、媒体/SmartArt、密码解密、宏/VBA 都**不在**本插件能力面内；先说明边界再给替代路径，详见 `references/scope-and-boundaries.md`。
- **安全默认值**：`open_*` 默认只读、`close_*` 默认不保存、`wps_batch` 默认遇错即停；要改原件/保存必须显式传 `readOnly:false` / `save:true`。

## 2. 确定任务类型

先归类，再动手。不同类型的流程不同：

| 任务 | 起手动作 |
|---|---|
| 编辑**已打开**的文件 | 读当前文件身份与相关结构，再确定要改的范围 |
| 编辑**路径指定**的文件 | `open_*`（Word/Excel/PPT 各一个）打开，确认打开的是哪一份，再改 |
| **新建**内容 | `create_*` 新建，拿到新对象的名字/路径，再写入 |
| 只读分析 | 只调读类工具；不要把"看一下"变成写操作 |
| 导出 / 转换 | 先保存，再导出；转换**必须显式传 `appType`** 并先确认输出路径 |
| 跨应用搬运 | 源侧读到结构化数据 → 目标侧整块写入 → 回读目标做对应关系核对 |

## 3. 定位目标与输出策略

目标可以是「某一份已打开的文档」「路径指定的文件」「新建的对象」。三种都要在执行前后**核对身份**。

- 唯一目标：直接推进，不要为常规选择打断用户。
- 多个候选（多份文档 / 多本工作簿 / 多份演示同时打开）且无法从路径、名称、上下文消歧：**只问缺失的那一项**（哪一份）。
- 目标已明确但参数名不确定：查 schema（见 §4），不要猜。

> **当前没有 documentId**：写操作落在「活动对象」上。传了名字参数（`sheet` / `presentationName` / `name`）能把目标收窄，但**活动对象仍可能被窗口焦点切换改掉**；插在两次调用之间的用户点击就是一处竞争窗口。所以：动手前读一次身份，改完后再读一次身份与内容，两者对得上才算落到目标上。这条只能缓解风险，**不能消除**。

## 4. 找工具与调用

1. 工具已在当前上下文里、参数也明确 → 直接调用。
2. 找不到能力 → `wps_help {app:"excel"|"word"|"ppt"}` 列目录，或 `wps_help {query:"关键词"}` 搜索（支持中文与中英混排，例如 `query:"关闭工作簿"`、`query:"新建 文档 create new"`）。
3. 参数不确定 → `wps_help {tool:"完整工具名"}` 取完整 schema，再按 schema 里的名字调用。
4. 未广告的工具 → `wps_call {tool:"...", args:{...}}`。
5. 搜不到就换关键词，或列一次应用目录；**不要无限搜索，也不要拼造工具名**。
6. 同一工具的 schema 在本任务里已知且未变 → 直接用，不必每次重查。

**未广告的工具只能用 `wps_call` 调用。** 服务端注册表里有它，不等于模型能直接按名字调用：模型能直接调用的名字只来自 `tools/list`（即 `reference.md` 里标「直达」的那些）。直接调一个未广告的名字会得到 `unknown tool`。

`wps_batch {calls:[{tool,args},…]}` 一次最多 50 项、顺序执行。它适合**彼此独立、失败后不会误写**的操作；有依赖的步骤（先建表再写数据）请逐项调用并检查每项结果。

## 5. 执行、验证与保存

### 5.1 执行

- 动手前读一次受影响的内容或结构（新建任务除外）。
- 破坏性或大范围操作前说清将影响的确切范围（区域 / 页 / 幻灯片 / 文件 / 对象）；范围含糊就先问清。
- 优先用整块操作：Excel 一次 `write_range` 写一块，不要逐格往返。

### 5.2 验证：验证什么

| 任务 | 最少要核对的东西 |
|---|---|
| 写数据 | 目标位置、实际区域、关键值（或整个小区域） |
| 写公式 | 公式文本、引用方向、计算结果 |
| 改格式 | 实际字体 / 样式 / 数字格式等被改的属性 |
| 排版 | 属性回读；能导出时再看渲染结果 |
| 保存 | 工具结果 + 输出文件真的存在（必要时独立读一次内容） |
| 调整页序 | 按最终顺序回读标题等身份特征 |
| 跨应用 | 源数据与目标内容的对应关系 |
| 删除 / 覆盖 | 目标已变，且**非目标部分没有变** |

小改动做局部核对；大范围变更用关键断言 + 抽样。不要把每次写入都变成全文件重读。

宿主读不了导出的图片时，只能说「内容与属性已核对，**视觉效果尚未验证**」，不要把"导出成功"写成"排版无误"。

### 5.3 保存、副本与关闭

用**任务意图**决定，不要用固定仪式：

- 用户要覆盖原文件 → 改完保存原目标（`wps_common_save`）。
- 用户要保留原件 → **先另存工作副本**（`wps_common_save_as {outputPath}`），确认后续改动落在副本上，再改。
- 用户要新建文件 → 先定输出路径，写完 `save_as` 落盘并核对文件存在。
- 用户没要求关闭 → **保持文档打开**，不要顺手关掉用户窗口。保存不必关闭。
- 未落盘的新文档被要求"保存并关闭" → 先 `save_as` 到明确路径，确认落盘，再关闭；没有路径时工具会明确报错而**不会**丢弃内容。

**保存 ≠ 备份。** `wps_common_save` 是写回当前文件、覆盖磁盘上的原件，它不提供回退点。需要回退点就自己先另存一份副本；也不要无差别地给别人没要求的文件生成一堆备份。

`wps_common_save_as` 的路径键是 `outputPath`。另存失败或没落盘时不要报告成功。

### 5.4 转换与导出

- `wps_convert_to_pdf` / `wps_convert_format` 支持 `appType`（excel/word/ppt）。**显式传**：不传时按 Excel → Word → PPT 取第一个正在运行的文档，Excel 常开着就会把"把 Word 转成 PDF"导成工作簿。
- 指定了 `appType` 却没有对应文档时会明确报错，不会退回别的应用。
- `openAfterExport: true` 会在导出后自动打开文件，结果里回报 `opened` / `failed`。

## 6. 失败恢复

先判断错误的性质，再决定动作 —— 不同性质的处理方式完全不同：

| 情况 | 该做什么 |
|---|---|
| 调用参数错误（缺必填 / 未知参数 / 形状不对） | 按错误里给出的 **schema 参数名**改一次；不要猜几个别名反复试 |
| 插件内部映射错误（错误里说的键来自**工具层发给桥**，不是你传的参数） | 记下动作名与原始错误，**改自己的参数修不了它**；换等价工具或如实上报 |
| 能力不存在 | 说明限制，用当前已有且可验证的替代做法 |
| 部分生效（`partial` / `shortfalls`） | 先读已生效的范围，**只补做缺失部分** |
| 超时 / 宿主被重启 | 状态未知：重新连接、核对后置条件，再决定是否重试 |
| 目标身份变了 | 停止对旧目标的写入，重新解析目标 |
| `warnings` | 主操作已完成、其中某些"尽力而为"的步骤失败；涉及用户关心的结果时如实转述 |
| `success:false` | 不要当成成功；把原始错误如实报出来 |

**超时后不得盲目重放非幂等操作**（插入文本、加幻灯片、追加行、插入图片…）：这类操作重复执行会写两遍。先读回确认上一次到底有没有落地，再决定下一步。

不要向用户承诺"可以撤销"：COM 改动不一定进撤销栈。

## 7. 报告结果

区分三件事，不要把"没验证"说成"已验证"：

- **已执行**：调用了什么、参数的关键值。
- **已核对**：回读到的具体值 / 结构 / 文件。
- **未验证**：视觉渲染、未回读的部分、用户需要自己确认的地方。
