# 稳定性加固计划（v0.2.x → v0.3.0）

> 背景：功能面已经收敛（267 个注册工具 / 69 个对外工具 / 广告预算 37,573 B ≤ 40,000 B），
> 下一阶段的目标不是"再加能力"，而是**让客户敢用、出问题能解释、坏不了数据**。
> 本计划只做稳定性，不新增业务能力；所有条目都必须有可运行的验收命令。
>
> 状态：**第 1 波（S1 + S2）已完成**（实现与实测见 `docs/FIXES.md` 52；新增 53 项断言）。
> 第 2～4 波尚未开工。S1 的落地方式与本文最初的假设**有两处不同**，已在原处标注。

## 0. 本轮判据

推广期的成功标准，按优先级排列：

1. **不卡死**——任何单次调用都不能把一个 DSH 会话永久钉住。
2. **不丢数据**——破坏性操作要么有前置守卫，要么事后能说清改了什么。
3. **报错能懂**——失败信息是中文、可操作、带动作名，不是裸 HRESULT。
4. **装得上、说得清**——安装摩擦有明确回退路径。

## S1（P0）模态弹窗围堵：客户现场的第一杀手 —— ✅ 已完成（实测修正了本节的假设）

**实测结论（WPS 12.1 x64，完整数据见 `docs/FIXES.md` 52）：这两条假设不成立，改法因此不同。**

| 本节原假设 | 实测结果 |
| --- | --- |
| `PasswordDocument:=""` 能挡住密码框 | **不能**。空串等于「没给密码」，框照样弹、照样卡死 |
| 扩展名不符（老 `.doc`）会弹转换框 | 这台 WPS **不弹**，18 秒内直接转换成功 |

真正有效的做法是传**非空哨兵密码**：加密 .docx 从「永久卡死」变成 **4 秒内报错**，
加密 .xlsx 变成 **1 秒内报错**（`0xFFF40006`），普通文档照常打开。
另外 `DisplayAlerts` 不是这道题的解（Word 侧本来就是 0，密码框照样弹），
且 WPS 的 IDispatch **不支持命名参数**，只能按位置传满 15 个参数。

**改动面（已实施）**
- `mcp/scripts/wps-com.ps1`：新增 `Set-WpsAlertsSuppressed` / `Restore-WpsAlerts` /
  `Open-WordDocument` / `Open-ExcelWorkbook` / `Open-PptPresentation` / `Format-WpsOpenError`，
  四个打开路径（`openFile` / `openWorkbook` / `openDocument` / `openPresentation`）统一走它们，
  `try/finally` 还原 `DisplayAlerts`，并把失败改写成「中文一句话 + 下一步建议」。
- `mcp/src/client/com-host.ts`：超时文案改为**状态未知**（可能被对话框阻塞）+ 明确下一步；
  新增 `suspect` 短超时机制（成功一次即恢复）；修掉两个恢复路径缺陷（陈旧子进程反杀新宿主、
  `ready` 帧误清 suspect）；下一次拉起宿主前等旧宿主真正退出。
- **偏离计划的一处**：计划要求超时后 `Stop-Process` 整个 WPS 进程树。实测本机有 **243 个**进程叫
  `wps`（还有 `et`/`wpp`/`wpscloudsvr`），而 Word/PPT 的 COM 对象**不提供 `Hwnd`**，
  无法可靠指认「被卡住的到底是哪一个」。照计划做会连带杀掉用户整套 WPS（含云同步与所有已打开文档），
  违反判据 2「不丢数据」，因此**不自动关 WPS**，改为讲清状态 + 短超时快速失败 + 宿主陈旧接管自愈。

**验收标准（已完成）**
1. `test/open-safety.test.mjs`：加密 .docx / .xlsx 在预算内返回且不弹框，普通文档照常，
   失败后 `ping` 仍通（证明没留下阻塞）——20 项全绿。
2. `test/watchdog.test.mjs`：超时文案含「状态未知」、下次调用走短超时、成功即恢复、
   4 次调用恰好 4 个请求（无静默重试）——15 项全绿。
3. `node scripts/verify.mjs` 与既有断言保持全绿。
4. 真机 fixture 生成后**校验文件真的加密了**，否则整份测试会为错误的原因通过。

**残余限制（如实记录）**：`Presentations.Open` 没有密码参数，加密的演示文稿仍会弹框；
缓解手段只有「先用 WPS 手工另存为不加密副本」。已写入 README「已知限制」。

**工作量**：约 1 日（含真机验证）。

**原始假设与证据（保留，作为「为什么改法变了」的对照）**：本节最初判断 `ConfirmConversions` /
`PasswordDocument` 在桥里出现 **0 次**、`openDocument` 只传路径（`$word.Documents.Open($p.path)`）、
`DisplayAlerts` 只覆盖 3 个 action，据此推断「老 .doc / 带链接 / 带密码文档会弹模态框」。
**弹框这半句是对的，但触发条件只有「带打开密码」这一类**；老 `.doc` 与扩展名不符的文件实测不弹。
修正后的实测表见本节开头。

## S2（P0）宿主单实例与并发语义 —— ✅ 已完成

**证据（原判断）**：**无**互斥锁、**无**心跳、**无**请求级看门狗；`timeoutFor(action)` 只区分长/短两类动作，
`inflight` 单请求串行——即"两个 DSH 会话同时用 WPS"这件事**从未被设计过**。

**风险**：客户很容易同时开两个窗口/两个会话。两个宿主进程各自持有 STA 并争抢同一个 WPS 实例时，
轻则互相阻塞，重则交叉崩溃；而现在的表现会是"莫名其妙卡住"，无法归因。

**改动面（已实施）**
- `host/wps-com-host.ps1`：启动时抢命名互斥体 `Local\dsh-plugin-wps-office-next-com-host`；
  已有宿主则回一句中文错误并**以非零码退出**，不硬上。
- 租约文件 `%USERPROFILE%\.wps-office-mcp\com-host.json`：记 `hostPid` / `clientPid` / 心跳 /
  当前 phase 与最近动作，售后可直接看出「谁在占着 WPS、卡在哪个动作上」。
- **陈旧接管**（互斥体本身做不到的部分）：只有能证明原主已死才接管——
  进程没了 / 它的 DSH-MCP 客户端没了（客户端通过 `WPS_OFFICE_CLIENT_PID` 自报）/ 心跳停摆 > 120s；
  接管只杀**那个陈旧宿主**，从不杀 WPS。
- README「重要注意事项」与排错表补了多会话行为说明。

**验收标准（已完成）**：`test/host-lease.test.mjs` 18 项——同时拉起两个宿主 → 第二个得到可读错误
（非零退出）而非超时；拒绝者不影响在位者；释放后新宿主接管；客户端已死的陈旧宿主**被接管而不是报假冲突**。

**工作量**：约 1 日。

## S3（P1）破坏性操作的数据安全审计

**证据**：桥内 `Delete()` **27 处**、`Clear()` 3 处、`ClearFormats()` 2 处、`ClearContents()` 2 处、
`Unlist()` 1 处、`ResetAllPageBreaks()` 1 处；目前只有 3 个 action 做了 `DisplayAlerts` 抑制。

**风险**：删表、删行、清空区域这类动作是客户真金白银的数据。现在的问题是**没有统一前置守卫**：
删掉一个非空工作表时既不提示、也不回传"删了多少行/多少列"。

**改动面**（逐条过一遍 27 个站点，产出清单）
- 对"可能丢大批数据"的动作加前置统计：返回 `deletedRows` / `deletedCells` / 原内容摘要（前 N 行），让 AI 能向用户复述。
- 明确哪些动作**必须**先 `Save` 或至少 `Saved=false` 保护（避免客户以为已保存）。
- 统一 `DisplayAlerts` 抑制范围到所有会触发确认框的破坏性 action。

**验收标准**：`docs/` 中新增"破坏性操作清单"表（动作 / 影响范围 / 是否回传统计 / 是否抑制弹窗 / 对应测试）；
每个"是"都必须有一条断言。

**工作量**：约 1～1.5 日。

## S4（P1）108 个工具从"能跑"到"被测试证明能跑"

**证据（本轮统计）**：267 个注册工具里**只有 159 个被测试点名**（PPT 最弱，76 个里 26 个被覆盖）。
而本项目历史上 **7 个"从来没工作过"的缺陷**（FIXES 38/39/40/43/47/49）**全部**落在无测试覆盖的路径上。

**改动面**
- 在 `scripts/e2e.mjs` 增加"**逐工具冒烟矩阵**"：对每个注册工具用最小合法参数调一次，断言
  `success:true` 或"明确的、预期内的业务错误"（例如缺文件、空选区），**禁止超时**。
- 覆盖顺序：**PPT（50 个未覆盖）→ Excel（33）→ Word（18）**，按客户使用频率而非数量排。
- 把"被点名工具数"做成 ratchet 账本（只许涨），照 `ALIAS_DEBT` / `UNTOOLED_ACTIONS` 的既有玩法。

**验收标准**：新账本写入 `test/spec-reproduction.test.mjs`；`node scripts/e2e.mjs` 打印覆盖率且 ≥ 目标值；
每发现一个真 bug → 在 `docs/FIXES.md` 追加编号（当前到 51）。

**工作量**：约 2 日（大头是真机跑数，不是写代码）。

## S5（P2）13 处空 `catch` 与静默失败

**证据**：桥内 242 个 `catch`，其中**13 个是空的**、52 个 `Add-WpsWarning`、72 个回错误 JSON、1 个 `continue`。
本轮人工核对：13 个空 `catch` 绝大多数是"COM 对象候选尝试"和关闭路径里的 `DisplayAlerts` 还原，属于**合理静默**。

**改动面**：不做"一刀切补日志"，而是
- 建立 `SILENT_CATCH_ALLOWLIST`，把 13 处（含行号与理由）**显式登记**；
- 新增测试：任何**新增**的空 `catch` 都必须先登记，否则测试失败；
- 复核 2 处位于 helper 内部、归属不清的（行 597 / 656）。

**验收标准**：空 `catch` 数量与 allowlist 长度一致；`param-contract` / 既有测试不变绿转红。

**工作量**：约 0.5 日。

## 明确"不做"的事（实测限制，禁止重试）

以下均为**本机实测无法实现**（不是没做，是 COM 层面不成立），推广材料里应表述为"不支持"而非"待开发"：

- Word 水印：页眉 `Shapes` 拒绝一切添加，`Count` 恒为 0。
- 文档属性：`BuiltInDocumentProperties` / `CustomDocumentProperties` 是空壳。
- Excel 切片器：`SlicerCaches.Add2` 可调用，但 `Slicers.Count` 恒为 0。
- 方案管理器：`Worksheet.Scenarios` 是 PSMethod，行为与预期不符。

## 纪律（沿用本项目既有约定）

- 先测量再改代码；每个结论都要有可运行命令。
- 账本只许"涨即失败、缩时显式改"。
- 广告预算红线：**≤ 70 个工具 / ≤ 40,000 字节**（当前 69 / 37,573）。
- 提交只写明确路径，**禁止 `git add -A`**（用户可能在另一会话同时改 `README.md` / `package.json`）。
