## 1. 一句话场景

**市政工程公司的标书专员陈伟**，投标截止前一夜要把他拼好的
《2026年市政道路提升工程_投标文件》**初稿**（Word）定稿打印：
封面独立、目录用罗马数字、技术方案要**横向 A3 + 双栏**、商务报价是宽表、附录反过来又回纵向——
现在他得手工插分节符、一节一节调页面设置、逐节改页眉页脚、把页码改成分节重编号，
**约 80 分钟，且最容易漏掉"某一节的页码忘了重开"和"封面被塞进了页眉"**，评标时直接扣分。

## 4. 现在手工怎么做（痛点）

1. 光标点到目录前 → 插入**分节符（下一页）**；技术方案前、商务报价前各再插一个（**3 次，位置全靠眼力**）；
2. 逐节双击页眉页脚，**先关掉"链接到前一节"**，再改写内容——这一步最容易漏，漏了就会出现"封面被塞进页眉"；
3. 第 3 节选中整节 → 页面设置 → **横向 + A3** → 再回第 4 节改回纵向（改方向会把边距整体旋转，得重设）；
4. 第 2 节分两栏 + 加分隔线；第 3 节再取消分栏（否则宽表被挤成两半）；
5. 页码：插入 → 页码 → 设置页码格式 → **编号格式选罗马数字**、**起始页码填 1**；
   第 3 节再来一次（起始 1，阿拉伯）；第 4 节这次要选"**续前节**"——**三个设置项手一抖就错一个**；
6. 目录：删掉手敲的那块 → 引用 → 自动目录（三级）；
7. 脚注：找到 `[1]` `[2]`，删掉方括号，用"插入脚注"重新做两处；
8. 报价表：加粗表头 + 底纹 + 勾"重复标题行" + 合并三组大类格 + 设边框 + 宽度自适应；
9. 全文查找替换三个词（**还得绕开表格里那处 `待定` 和两个产品名**）；
10. 另存定稿 → 导 PDF → 数页数报给领导；**每次都有人在这里漏掉"某一节的页码没重开"，评标直接扣分**。

**耗时约 80 分钟；每次改稿都要重来一遍。**

顺序与 S1–S6 相同，**只有 known-good 全绿且每个单缺陷 broken 集在对应项变红，才允许让模型真机跑场景**：

```powershell
$py = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py test\.artifacts\scenario-s7\tools\make_fixture.py       # 造脏初稿 + %TEMP%\s7-grading\expected.json
& $py test\.artifacts\scenario-s7\tools\make_known_good.py    # 造 known-good.docx / 每个单缺陷 broken.docx
& $py "%TEMP%\s7-grading\selfcheck.py"                        # exit 0 才允许开真机
```

**验证器陷阱（写核验器时先堵住）**：

| # | 陷阱 | 对策 |
| --- | --- | --- |
| 1 | 节数：`w:sectPr` 有 **body 末尾那一个** + 每个分节符处内嵌的。数错就会把 4 节读成 3 节或 5 节 | 统一用 `body.xpath('./w:p/w:pPr/w:sectPr')` + 末尾 `./w:sectPr` 的口径，并在 fixture 里先打真值 |
| 2 | 横向判定：`w:pgSz/@w:orient="landscape"` 可能缺省而由宽高比表达 | 同时接受 `orient` 属性与 `w > h` 的推断，两者不一致时记红并留证 |
| 3 | 页码格式：WPS 可能写 `<w:pgNumType w:fmt="lowerRoman"/>`、也可能写 `w:fmt="i"` 之类的别名，或把 `w:start` 放进不同的节 | 按 **ON/XML 归一化**读：`lowerRoman` / `lowerLetter` / `decimal` 三种归一类，`start` 缺省表示"续前节" |
| 4 | "续前节"没有显式标记，**缺 `w:start` 就是续前节** | C4 只在"显式带 start 且 ≠ 继续语义"时判红，避免把正确写法判错 |
| 5 | `w:headerReference` 指向的 part 里可能只有空段落（"有引用但无内容"= 封面） | B8 判"内容为空"而不是"引用不存在"；反之 B7 判"引用存在"而不是"内容非空" |
| 6 | 中文字体 / 加粗：表头加粗可能落在 `w:rPr/w:b`，也可能来自表格样式 | 直读 `w:tblStyle` 与单元格 `w:rPr` 两处，任一为真即通过，并记录来源 |
| 7 | 底纹 `w:shd` 可能在 `tcPr` 也可能在 `tblPr` | 两处都读，取最具体的一处 |
| 8 | 合并单元格：`w:vMerge` 的 `restart` / `continue` 是**列内**配对；空白 `w:vMerge` 等价 `continue` | 先解析网格再判组数，不按"读回空字符串"判（`get_table_data` 的注释已警告这一点） |
| 9 | 脚注：`word/footnotes.xml` 里**默认带两条分隔符脚注**（`separator` / `continuationSeparator`） | 只数 `w:footnote` 且 `type` 属性缺失（或缺省）的那些 |
| 10 | 目录：可能是 `w:fldSimple`、`w:instrText`，也可能是 SDT | 三种都认；级别写死与否不影响判定 |
| 11 | PDF 中文提取可能失败 | 只判文件头 + 页数，提取不到中文只记录 |
| 12 | 核验器的"假指控"风险（S3/S6 各栽过一次） | known-good 必须**全绿**；每个 broken 集**只在设计好的那一项变红**，其余项必须仍绿 |

## 8. 已知不可判项

- 「手工 80 分钟」是场景设定，不是断言。
- 排版**好不好看**、目录数字与页码是否视觉一致、PDF 与 docx 是否视觉一致：不判。
- 分栏的**实际栏宽**、栏间距的美观度：不判（只判 `w:cols/@w:num` 与 `w:sep`）。
- 页数：`get_document_stats` 回报的页数是 WPS 排版结果，python-docx 不复核 → 只判"是数字"。
- PDF 页数与 docx 页数是否一致：不判。
- 模型是走插件工具还是走 python-docx 直写：**判据只看产物**（S4/S5 已有先例），但若它绕开插件，§9 会把"插件那条路能不能走通"单独探针量一次。

## 9. 待验证的疑点（**假设，不是结论** —— 跑之前先列好，避免事后编解释）

> 标注「**源码已读**」的几条来自本轮只读取证，不是猜；其余是待实测。

| # | 疑点 | 依据 |
| --- | --- | --- |
| H1 | **`setPageSetup` 改的是全篇、不是某一节**：桥代码里是 `$ps = $doc.PageSetup`，**没有 `section` 参数**；而同族的 `getPageSetup` 有 `section`、按节读 | **源码已读**（`host/wps-actions.ps1:6077-6082` vs `:6049-6057`）。预期现象：第 1、2 节设纵向后，第 3 节设横向会把**前面所有节**一起转横 |
| H2 | `insertPageNumbers` **没有"起始页码"与"编号格式"参数**（只有 `section`/`position`/`alignment`/`showFirstPage`/`includeTotal`），而验收要求"罗马数字 + 分节重开 + 续前节" | **源码已读**（`host/wps-actions.ps1:1553`）；WPS GUI 显然有这个功能，问题是**桥有没有暴露** |
| H3 | 若 H1/H2 成立，模型只能靠 `wps_call` + `wps_execute_method` 逃生舱或 python-docx 绕过 —— 那么"插件能不能做多节版式"的答案是"不能，但模型能绕" | 与 R11「如实报失败」直接相关：**要观察它是明说做不到、还是回一个假的 success** |
| H4 | `insertSectionBreak` 依赖**当前选区**插入，且工具**不在广告面**（`advertised: false`） | **源码已读**（`:7206-7224`、`:8249`）。观察它 4 次插入能否落到正确位置、是否插多了/插少了 |
| H5 | 分栏（`w:cols`）与"宽表占满整页"是否冲突：第 3 节设横向后**若分栏没取消**，宽表会被压成两半 | 分栏是**节级**属性，模型必须理解"栏是跟着节走的" |
| H6 | 表格跨页重复表头（`tblHeader`）**没有任何工具对应**（`set_table_format` 只有 style/borders/autoFit/headerShading）。WPS 的 `Rows(1).HeadingFormat` 是不是又一个"空壳属性"？ | 属未知能力；**若做不到，必须在场景卡/报告里如实记为能力缺口**（而不是当模型失误） |
| H7 | 页码"共 Y 页"（NUMPAGES）在**多节**下会不会把"续前节"算错 | `includeTotal` 已有实现，但历史上只在单节文档量过 |
| H8 | 脚注：`wps_word_add_footnote` 是"在光标处插入"，需要先定位；`get_notes` 能否读回注文 | 脚注族从没进过真实场景 |
| H9 | 另存为后再改，会不会把**初稿**也改掉（违反"初稿一个字都别动"） | S2 在 Word 单节上已验过一次，多节 + 多次改页面设置是新的压力面 |
| H10 | 目录在**多节 + 分栏**文档里生成的位置与条目是否正确（封面标题不应进目录） | 上一轮 S2 只验过单节目录 |

疑点被证伪也照样如实记录（说明这条链路没问题），不为了"有发现"而凑结论。
